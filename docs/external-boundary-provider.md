# External boundary provider

Eqiora's first external boundary-provider path is a bounded application
composition for the accepted prescribed dynamic-solid occurrence. The
application owns process launch and configuration, then transfers one
already-connected child process to Eqiora. Eqiora does not discover providers,
select executables, or own a general plugin system.

The one-shot session projects only the exact displacement and velocity boundary
traces from the accepted prior State. The provider returns one deterministic
stateless lagged total-displacement candidate. The accepted profile uses
ordinary-GIL CPython 3.12 and NumPy 2.1.0, with `model_sha256` binding the
provider exchange to the exact Model identity.

Framing and decoding are bounded. Cancellation, timeouts, malformed input,
unexpected process exit, and write failure poison the session, terminate the
child, and publish no partial owner. A successful candidate is bitwise-admitted
through the unchanged structural path before any durable product is published.

The occurrence artifact preserves the provider, adapter, exact projection,
request, candidate, transcript, admission, and accepted-State roles. The direct
#365 Run remains byte-for-byte unchanged with the accepted-next State as its sole
output. E1 creates a separate Run whose two sorted outputs are that unchanged
State and the complete admitted provider occurrence.

Verification is limited to the exact affine Python profile above. Arbitrary
Models, meshes, Fields, boundaries, steps, providers, launch and discovery,
session reuse, traction exchange, two-way coupling, remote execution,
performance, and scale remain nonclaims. See
[`interfaces.prescribed-dynamic-solid-subprocess-provider-3d`](../verify/interfaces/prescribed-dynamic-solid-subprocess-provider-3d/README.md)
for the registered evidence case.
