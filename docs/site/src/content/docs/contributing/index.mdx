Eqiora welcomes focused contributions that preserve its meaning-first architecture and evidence discipline.

## Before opening a change

1. Read the <ExactSourceLink path="CONTRIBUTING.md" kind="blob">contribution guide</ExactSourceLink>.
2. Check the <ExactSourceLink path="docs/architecture.md" kind="blob">architecture</ExactSourceLink> and <ExactSourceLink path="docs/glossary.md" kind="blob">glossary</ExactSourceLink>.
3. Search existing issues and RFCs before introducing a public concept.
4. Keep one capability claim bounded enough to verify and review, and reuse accepted contracts rather than rebuilding its full stack.

New public semantics, wire formats, stable interfaces, dependency-layer exceptions, numerical contracts, or governance changes require the <ExactSourceLink path="rfcs/README.md" kind="blob">RFC process</ExactSourceLink>.
